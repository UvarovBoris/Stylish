# AI Agent Guidelines: Modern Android Development (Stylish)

This document establishes the architectural, structural, and coding standards for developing the **Stylish** Android application. All AI coding assistants (Antigravity, Cursor, Gemini in Android Studio, Claude Code) must strictly follow these rules.

---

## 1. Tech Stack & Core Philosophy

- **Language:** Kotlin 2.x (idiomatic, null-safe, functional, immutability by default).
- **UI Framework:** 100% Jetpack Compose + Material Design 3. Never use legacy XML layouts, DataBinding, ViewBinding, or Fragments.
- **Architecture:** Clean Architecture + Unidirectional Data Flow (UDF).
- **Dependency Injection:** **Dagger Hilt** exclusively.
- **Navigation:** **Navigation 3 (`androidx.navigation3`)**. Do NOT use Navigation 2 (`NavHostController`, `NavHost`, `composable("route")`).
- **Asynchronous & Reactive:** Kotlin Coroutines (`CoroutineScope`, `Dispatchers`) + Flow (`StateFlow`, `SharedFlow`). Never use `LiveData` or RxJava.
- **Build System:** Gradle with Kotlin DSL (`build.gradle.kts`) and Gradle Version Catalog (`gradle/libs.versions.toml`).

---

## 2. Navigation 3 (`androidx.navigation3`) Guidelines

Navigation 3 is state-driven and decouples navigation state from UI representation.

### Key Rules:
1. **Serializable Keys:** All destination keys MUST be `@Serializable` data objects or data classes.
   ```kotlin
   @Serializable
   data object HomeRoute

   @Serializable
   data class ProductDetailRoute(val productId: String)
   ```
2. **User-Owned Backstack:** Navigation state is maintained via an observable list (e.g. `mutableStateListOf` or custom state holder), NOT a hidden `NavController`.
   ```kotlin
   val backStack = remember { mutableStateListOf<Any>(HomeRoute) }
   ```
3. **NavDisplay & Entry Provider:** Render destinations using `NavDisplay` and `entryProvider`:
   ```kotlin
   NavDisplay(
       backStack = backStack,
       entryProvider = entryProvider {
           entry<HomeRoute> {
               HomeScreen(
                   onNavigateToDetail = { id -> backStack.add(ProductDetailRoute(id)) }
               )
           }
           entry<ProductDetailRoute> { key ->
               ProductDetailScreen(
                   productId = key.productId,
                   onBackClick = { backStack.removeLastOrNull() }
               )
           }
       }
   )
   ```
4. **Back Navigation:** Manage device back button using `BackHandler(enabled = backStack.size > 1) { backStack.removeLastOrNull() }`.
5. **No Legacy Nav 2 APIs:** Never introduce `NavController`, `rememberNavController()`, `NavGraphBuilder`, or string-based routes.

## 3. Dependency Injection (Hilt)

1. **Application:** The root `Application` class must be annotated with `@HiltAndroidApp`.
2. **Activities:** `MainActivity` must be annotated with `@AndroidEntryPoint`.
3. **ViewModels:** Every ViewModel must be annotated with `@HiltViewModel` and inject dependencies via `@Inject constructor(...)`:
   ```kotlin
   @HiltViewModel
   class ProductDetailViewModel @Inject constructor(
       private val getProductUseCase: GetProductUseCase,
       private val savedStateHandle: SavedStateHandle
   ) : ViewModel()
   ```
4. **Modules:**
   - Organize modules under `di/` packages (e.g. `NetworkModule`, `DatabaseModule`, `RepositoryModule`).
   - Use `@InstallIn(SingletonComponent::class)` for singletons or `@InstallIn(ViewModelComponent::class)` where appropriate.
   - Prefer `@Binds` over `@Provides` for abstract interface bindings to reduce generated bytecode.

## 4. UI Layer & Jetpack Compose Best Practices

### Stateful vs. Stateless Separation
Every screen must be split into two composables:
1. **Stateful Container (`*Route` or `*Screen`):**
   - Injects the ViewModel via `hiltViewModel()`.
   - Collects state using `collectAsStateWithLifecycle()`.
   - Translates UI events into ViewModel function calls or navigation actions.
2. **Stateless Content (`*Content`):**
   - Takes immutable state (`UiState`) and event lambdas.
   - Contains no ViewModel references.
   - Easily previewable with `@Preview` and testable in isolation.

```kotlin
@Composable
fun ProductDetailScreen(
    productId: String,
    onBackClick: () -> Unit,
    viewModel: ProductDetailViewModel = hiltViewModel()
) {
    val uiState by viewModel.uiState.collectAsStateWithLifecycle()

    ProductDetailContent(
        uiState = uiState,
        onBackClick = onBackClick,
        onAddToCart = viewModel::addToCart
    )
}

@Composable
fun ProductDetailContent(
    uiState: ProductDetailUiState,
    onBackClick: () -> Unit,
    onAddToCart: () -> Unit,
    modifier: Modifier = Modifier
) { ... }
```

### Parameter Ordering Standard
1. `modifier: Modifier = Modifier` (first optional parameter)
2. Required data / state parameters
3. Optional configuration / styling
4. Event lambdas (`onAction: () -> Unit`)
5. Trailing composable lambda (`content: @Composable () -> Unit`, if applicable)

### Performance & Stability
- Always expose a default `modifier: Modifier = Modifier` on reusable components and apply it to the outermost layout node.
- Use `key` in `LazyColumn`/`LazyRow` items (`key = { item.id }`).
- Wrap complex or non-primitive collections in `@Immutable` / `@Stable` data classes or use `ImmutableList` from `kotlinx.collections.immutable` to avoid unnecessary recompositions.
- Use `derivedStateOf` when deriving state from rapidly changing observables (e.g. scroll offsets).
- Never instantiate heavy objects or coroutine dispatchers inside composable functions without `remember`.

## 5. State Management & Architecture (UDF)

- **Single Source of Truth:** ViewModels expose a single immutable `StateFlow<UiState>`:
  ```kotlin
  private val _uiState = MutableStateFlow(ProductUiState())
  val uiState: StateFlow<ProductUiState> = _uiState.asStateFlow()
  ```
- **Atomic State Updates:** Always update state via `_uiState.update { it.copy(...) }`.
- **One-off Events:** Use Kotlin Channels (`Channel<UiEvent>(Channel.BUFFERED)`) consumed as a `Flow` or handle actions directly as state changes.
- **Clean Architecture Layers:**
  - **UI Layer:** Composable screens + ViewModels + UiState.
  - **Domain Layer:** Pure Kotlin business models and single-responsibility Use Cases (`operator fun invoke(...)`).
  - **Data Layer:** Repositories, Local (Room / DataStore), Remote (Ktor / Retrofit). Expose data as `Flow<T>` or `Result<T>`.

---

## 6. Gradle & Dependency Management

- **Version Catalog:** ALL libraries, plugins, and compiler versions MUST be defined in `gradle/libs.versions.toml`.
- **Never Hardcode Versions:** Do NOT hardcode dependency strings or versions in `build.gradle.kts`.
- **Kotlin DSL:** Use type-safe accessors (e.g. `libs.androidx.compose.ui`).

---

## 7. Testing & Quality Standards

- **Unit Tests:** MockK + JUnit 5 / JUnit 4.
- **Flow & Coroutine Tests:** Use `kotlinx-coroutines-test` (`runTest`, `StandardTestDispatcher`) and **Turbine** for testing Flows.
- **Compose UI Tests:** Use `createComposeRule()` or `createAndroidComposeRule<MainActivity>()`.
- **No Wildcard Imports:** Never use `import foo.bar.*`.
- **String Resources:** Never hardcode user-facing strings; use `res/values/strings.xml` and `stringResource(R.string.xxx)`.
